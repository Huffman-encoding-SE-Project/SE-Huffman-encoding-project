## C. Implementation Summary

### C.1 Project Setup and File Input

The project repository and initial folder structure were established to organize the source code and supporting files.

The command-line input and file-reading functionality allows the program to receive an input file and read its contents for Huffman processing.

### C.2 Byte-Frequency Counting

The program counts the occurrences of each byte in the input file. These frequency values are used by the Huffman tree construction stage.

Since the program works with byte values, the frequency-counting stage is intended to handle general file data rather than only ordinary text characters.

### C.3 Huffman Tree Construction

The Huffman tree is constructed using the calculated byte frequencies. The tree combines the least-frequent nodes step by step until a single root node represents the complete input.

The resulting tree provides the structure required to generate Huffman codes.

### C.4 Huffman Code Generation

Huffman codes are generated by traversing the constructed tree. Each symbol receives a code based on its path through the tree.

The method assigns shorter codes to more frequent symbols and longer codes to less frequent symbols, forming the basis of Huffman compression.

### C.5 Initial Compression Workflow

The initial command-line processing workflow follows these main stages:

1. Read the input file.
2. Count the frequency of each byte.
3. Construct the Huffman tree.
4. Generate Huffman codes.
5. Use the generated codes in the compression process.

Sprint 1 established these foundational components and integrated them into the initial program.

## F. Illustrative Processing Logic

The following pseudocode summarizes the high-level Huffman processing flow. It is explanatory and is not a verbatim extract from the repository.

### F.1 Initial Huffman Processing

```text
function process_input(input_path):
    input_bytes = read_file_as_bytes(input_path)

    frequencies = count_byte_frequencies(input_bytes)

    huffman_tree = build_huffman_tree(frequencies)

    code_table = generate_huffman_codes(huffman_tree)

    compressed_output = encode_input(input_bytes, code_table)

    write_compressed_output(compressed_output)
```

### F.2 Component Relationship

The initial implementation separates file handling and Huffman processing into modules. File input supplies the bytes, frequency counting produces the frequency table, tree construction uses that table, and code generation uses the resulting tree.

This modular organization makes the individual components easier to integrate and test.
